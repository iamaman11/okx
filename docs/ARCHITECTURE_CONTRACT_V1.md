# Current ownership contract — clean Engine (#398)

The **only normative specification** is [issue #398](https://github.com/iamaman11/okx/issues/398), including [16→7 capability parity and acceptance tests](https://github.com/iamaman11/okx/issues/398#issuecomment-6373732525). This page records actual owners/invariants, not an independent roadmap or a claim that all planned features are already delivered. [Older architecture](history/ARCHITECTURE_CONTRACT_V1-before-398.md) is non-normative evidence.

**Worker:** OAuth and typed seven-tool MCP public surface; central persistent governance revisions and one global RiskBook; one native-result projection. Worker neither submits exchange orders nor offers arbitrary RPC/SQL.

**Rust Engine:** independent verified AccountKey (venue/environment/UID) contexts and public/private sources; one TradeService for manual and automatic strategies; protected order execution and reconciliation. An alias, view or changed strategy cannot redirect an intent to another UID. The 16→7 live business-parity and exact-release F09 acceptance remain tracked in #398.

**SQLite:** one WAL AccountStore writer per verified AccountKey; durable plans/intents/orders/fills/bills/finance/policy/source cursors; indexed, bounded addressable queries. Missing or corrupt SQL is an error, never a new installation trigger. Old v14 history, legacy grants and mode-switch migrations are not supported. Research uses immutable artifacts plus bounded CPU/cache; **indexed SQLite WAL research job metadata (F08) is separate from immutable content-addressed research artifacts**. There is no second finance ledger.

**CONTROL:** verified Windows Agent/Controller/Launcher deployment, lifecycle, autostart, backup and restore. It does not decide trading policy or select an exclusive account profile. GitHub encrypted DATA is for read-only diagnosis only; GitHub issue #12 CONTROL remains the typed lifecycle route. Primary application transport is authenticated generation-bound WSS.

**Seven MCP tools:** `accounts`, `strategies`, `market`, `research`, `trade`, `portfolio`, `diagnostics`; finite versioned DTO actions only, never an eighth tool or a free-form shell/SQL/venue gateway. A useful old business function must be implemented inside one of these seven or explicitly retired by decision in #398. Do not restore legacy begin/finalize/rearm ceremonies as trading prerequisites.

**Risk and durability:** persistent account access does not grant per-order permission. Central USD10 aggregate Real loss including costs and held modeled risk is global across accounts, instances and restarts; profits never replenish it, and owner-only lowering cannot reset/increase it. Every risk-increasing POST requires fresh UID/account/market/venue evidence, source generation, fees, position mode, central CAS reservation, protection and STOP/UNKNOWN gates. Begin-post commits durably before the single exchange call; UNKNOWN is reconciled by exact intent identity, never reposted. Owner-proven safe exits remain available on pause. Restart preserves SQL, policy and uncertain outcomes without InitializeInstallation/InitializeAccount.

Read [operator contract](chatgpt-operator-contract.md) for actions, [product acceptance](PRODUCT_ACCEPTANCE.md) for CONTROL/test gates, and [status ledger](ROADMAP.md) for dated verified progress. `CODE_PASSED`, `INSTALLED_MATCHED`, `CAPABILITY_PARITY` and Real physical evidence are independent.
