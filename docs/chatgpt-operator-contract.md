# Operator contract: one Engine (#448)

Use normative [#448](https://github.com/iamaman11/okx/issues/448) and the single [#449 implementation cursor](https://github.com/iamaman11/okx/issues/449). [#398 product acceptance](PRODUCT_ACCEPTANCE.md) and [former staged contract](history/chatgpt-operator-contract-before-398.md) are historical baselines, not independent current runbooks.

Use the authenticated Cloudflare MCP tools accounts, strategies, market, research, portfolio and diagnostics, plus the seven explicitly risk-annotated trade.* operations. Only call actions actually advertised by the connected current schema; the historical 16→7 tool reduction in #398 is not the current public tool-count contract. Always give the explicit account reference required by a mutation; instance IDs do not replace account identity. Credentials stay in the native protected owner and tools receive named references only. A connected account keeps its requested access across restart and connection of another account. Pause/resume is one ordinary account action; technical proof IDs and rearm are absent.

Market/research do not require trading activation or previous OOS work. Preserve missing-data, counterfactual and partial labels. Research returns durable job IDs; query status/results or cancel through the same job. Batch results and parameter choices are independent per instrument. Portfolio reports SQL-backed money, flows and coverage; a gap is not zero PnL.

Create/update/start/stop strategy instances with explicit versioned parameters and budgets. Both manual and automatic decisions use the same native executor. Preview is informative and does not reserve a permanent right to POST. Execute supplies one idempotency key and bounded deadline; retry that same body/key only when the result permits it. UNKNOWN requires status/reconciliation of the same intent. Never issue a replacement POST to diagnose an uncertain effect.

Protect every new exposure. Close/cancel/reduce only proven owned exposure; a pause or loss-budget stop does not disable safe reconciliation and exits. Changing account alias, view, instance parameters or local files cannot grant another UID or reset the campaign. Do not publish UID, balances, raw private responses or credentials in public GitHub evidence.

The authorized physical campaign uses Real operations with aggregate losses including fees at most USD10, one test position at a time and two small OPEN -> verified protection -> CLOSE cycles. Independently verify flat positions/orders/algos/UNKNOWN/reservations between cycles; restart occurs flat. Profits do not replenish that budget. No second authorization or staged period is required. If size/protection/costs cannot fit, report the actual blocker without increasing limits.

Use diagnostics with an intent/client/job/artifact reference for one bounded causal result. Retain the reason, scope, source time/generation, retryability and next action. A healthy connector is not a successful trade admission. A fixture result is not physical multi-account acceptance. If no second verified Real account exists, record PHYSICAL_MULTI_ACCOUNT=BLOCKED explicitly.

Issue12 CONTROL remains typed process/install/backup/restore operations; inspect the terminal result by request ID. Native binaries must come from the exact successful CI bundle through the existing verified install chain. No local rebuild replaces it. The checked-in acceptance manifest records preinstallation code evidence; the final acceptance.json attached to the exact GitHub release records installed and exchange observations.
