This is an evidence procedure for the implemented clean Engine. Code fixtures, deployment identity and exchange acceptance are separate results. A test that reads a source string cannot replace an executed state transition, financial transaction, scheduler test or authenticated MCP request.

Run `python scripts/acceptance_product.py --run` from the repository. It executes workspace tests with their real names and counts, strict Clippy and the Worker suite; saves complete logs; validates all eight requirement IDs; and writes `acceptance.json`. A nonzero exit means unfinished or failed code acceptance. `--code-log path` imports an actual earlier Rust test log. The runner refuses zero executed tests and uses exact scenario names rather than substring classification. CODE_PASSED requires every format, architecture, SQL, product-contract, Rust, Clippy and Worker check; importing a Rust log alone cannot establish it. `python scripts/acceptance_product.py --self-test` checks the evidence validator itself and does not claim product acceptance.

Run `cargo run -p okx-research --release --example analytics_bench` and save its JSON as `docs/acceptance/398/analytics-performance.json`. It prepares deterministic numeric bars once, performs five warmups and thirty timed EMA 20/50 replays over 8,640 15-minute bars, and executes the 100-variant, 100,000-bar grid. Windows peak working set comes from GetProcessMemoryInfo, not a dataset-size estimate. The JSON records CPU, OS, logical CPU count, fixture hash, p50/p95/max, throughput, summary size and peak incremental memory. The checked measurement machine has 34,278,834,176 bytes of physical RAM. Network acquisition is outside this compute measurement.

`prepared_screen_8x100_latency_and_response_budget` measures native fixture compute, projection and serialization for eight instruments with 100 closed bars and return/volatility/spread fields. `two_heavy_research_jobs_ingestion_stop_and_cancel_latency` executes two real causal grids on blocking workers alongside simulated ingestion, samples the STOP timer thirty times, then confirms cooperative cancellation. Both emit `ANALYTICS_PERF_JSON` records; the acceptance runner merges these from actual test logs. They do not measure Cloudflare or the public exchange network. Five real cold/warm public requests, authenticated MCP transport bytes and installed release checks must be recorded separately during physical acceptance.

The default computation limits are 100 screen instruments, one million input bars, 100 grid variants, source concurrency four per request/eight globally, a 256 MiB cache, CPU workers `max(1,min(4,logical_cpus-1))`, queue 32, and two heavy jobs. Replay rejects an estimated working set over 256 MiB before allocating its result. CPU cancellation checks run at most every 4,096 bars and between variants. Results use content-addressed immutable dataset chunks, trade pages of 50 rows, equity pages of 4,096 points, and a durable research catalog. Restart changes queued/running jobs to interrupted, preserving completed artifacts. Seven-day retention removes unpinned terminal results only after checking references; active jobs protect their working sets. The catalog preserves request identity after artifact expiration.

EMA uses only the closed bar at t and executes at the next open. Warmup is not scored. Position changes incur taker fee and adverse slippage; funding is signed by held exposure and contract multiplier. Stop wins when stop and take-profit are both reachable in a bar; a gap fills at the adverse open rather than the unreachable stop price. Spot permits long/flat; linear derivatives require an explicit multiplier from the current public reference and are marked counterfactual. Historical-observed mode rejects absent historical fee/rule evidence; current rules are never described as historical evidence. A single chronological 70/30 split selects on train Sharpe with turnover tie-break, then reports the untouched test partition. Exact Decimal monetary totals are included alongside analytic floating-point ratios.

A research batch accepts 1–8 unique instruments, up to 1,000,000 closed bars in total and 100 grid parameter variants. Each instrument has its own replay or chronological train/test grid. The summary labels `independent_instruments`; sums of independent backtest PnL are not portfolio PnL. `research.result` pages instrument rows and trade slices with `instrument:<index>:<offset>`. Dataset and result artifacts use immutable content addresses. SQL strategy definition versions bind each intent to the original definition/parameters digest, unaffected by later updates. Public grid selected/train/test/equity views remain incomplete until F05; job metadata is still JSON pending F08. Do not claim either is accepted.

Intent transitions are enforced by the addressed SQL owner:

| Current state | Allowed next state | Durable action and external side effect |
| --- | --- | --- |
| Absent | PREPARED | Insert immutable decision/plan and body-bound idempotency receipt; no exchange POST |
| PREPARED | RESERVED | Persist the matching central reservation receipt; no exchange POST |
| PREPARED / RESERVED, no begin-post | REJECTED | Record a proved unsent outcome and pending central release |
| RESERVED | POSTING | Check deadline, policy/definition revision and gates; commit begin-post exactly once before one gateway invocation |
| POSTING / UNKNOWN | UNKNOWN, ACKNOWLEDGED, PARTIALLY_FILLED, FILLED, CANCELLED, REJECTED | Record exact exchange readback or owner-confirmed unsent rejection; UNKNOWN never permits a replacement POST |
| ACKNOWLEDGED | ACKNOWLEDGED, PARTIALLY_FILLED, FILLED, CANCELLED | Addressed exchange reconciliation |
| PARTIALLY_FILLED | PARTIALLY_FILLED, FILLED, CANCELLED | Reconcile actual filled quantity and protection; cancel preserves filled ownership |
| FILLED / CANCELLED / REJECTED | Same terminal state | Idempotent observation; no reopening of that intent |
| Central receipt active | RELEASED | Release only after the exact owned exposure and orders are terminal; record central acknowledgement |

Restart converts POSTING to UNKNOWN and continues readback. Filled entries retain central occupancy while their lots remain open. Protection failure records STOP and enters the owned cancellation/compensating-close path. A strategy update appends a definition; start/stop advances its policy revision. Existing plans never silently adopt new parameters. Research jobs transition queued -> running -> completed/failed/cancelled; restart marks queued/running interrupted and retains completed instrument artifacts.

Native admission defaults are `QUOTE_MAX_AGE_MS=2000` and `ACCOUNT_MAX_AGE_MS=5000` in `config.rs`; future, missing and over-age receipts are rejected. Boundary tests cover the exact TTL and TTL+1 millisecond. A restored account uses a bounded 60-second historical audit to a common cutoff, followed by fresh current account/orders/algo/protection/central evidence. Source timestamps reflect the earliest actual response in a combined read. SQL commit rechecks freshness; gate clearance does not bypass ordinary central reserve admission.

Operational bounds: native read concurrency 8, total pending dispatches 64, account mutation capacity 128, SQL actor queue 128, risk channel/pending responses 32, account registry 32, restore active receipt proof 256, independent maintenance accounts 4. Native heartbeat is 15 seconds with a 35-second timeout. Safe connection reads back off 1/5/15/30/60 seconds. This reconnect policy never retries an uncertain exchange POST.
